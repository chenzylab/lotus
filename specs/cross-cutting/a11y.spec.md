# 横切能力 SPEC — 无障碍 (Accessibility)

> 设计依据：`specs/references/semi-design-articles.md` 「Accessibility」一节，遵循 WCAG 2.0 + ARIA。

## 适用范围

所有组件，无一例外。这是唯一一项没有"部分组件豁免"的横切能力。

## 强制检查项（对照 `.claude/skills/a11y-audit/SKILL.md` 逐项执行）

### 色彩与对比度
- 常规文本对比度 ≥ 4.5:1，大文本（≥18px）≥ 3:1
- 交互状态（hover/active/focus）与相邻背景色对比度 ≥ 3:1
- 描边类组件的描边色与底色对比度 ≥ 3:1
- 不使用颜色作为唯一视觉提示（需搭配图标/文本/下划线/纹理等冗余信息通道）
- 深色模式不使用纯黑背景

### 键盘导航
- Tab / Shift+Tab 可完整遍历所有可交互元素，且遍历顺序符合视觉/逻辑顺序
- 方向键用于组内导航（如 Radio 组、Menu 项、Tab 项）
- Enter / Space 激活操作
- Esc 关闭浮层类组件
- 初始焦点位置按操作风险分配：破坏性操作（删除确认）焦点落在最安全选项；常规流程（继续/确认）焦点落在推荐操作
- 浮层/模态关闭后，焦点必须归还到触发它的元素（不是归还到 `body` 或丢失）

### 语义化
- 优先使用原生语义元素（`button`/`input`/`label` 等），只有自定义交互组件才补充 ARIA
- ARIA 属性至少覆盖：角色（role）、状态（aria-selected/aria-expanded/aria-disabled 等）、位置信息（列表类组件的 aria-posinset/aria-setsize）

### 媒体
- 图片提供 `alt`；图标+文字组合按钮的图标部分不重复提供 alt（避免屏幕阅读器重复播报）
- 音视频内容提供字幕/文字轨道

### 动画安全性
- 任何内容每秒闪烁不超过 3 次
- 流式/持续更新内容（如 Phase 6 的 AiChatDialogue）使用合理的 `aria-live` 策略（`polite` 为默认，避免打断朗读；只在关键节点如生成完成时才用 `assertive`）

### 布局
- 200% 缩放下内容仍可读、功能仍完整
- 长内容分段展示，避免超长无结构段落

## 验收标准

- [ ] 每个组件在其 Phase SPEC 验收清单打勾前，已过本文件的强制检查项（不是可选项）——这是汇总性检查，本身不是可以直接实测的静态属性。本文件其余 4 条验收标准现已全部核实/落地（45-48 行），但第48行新接入的 axe-core 自动化扫描首次全量运行即命中 665 条 critical/serious 级别记录，尚未逐条核实排查，不能排除其中有真实的、之前人工 checklist 遗漏的组件级缺陷。因此本条暂不勾选——不是"每个组件都没过检查"，而是"新增的自动化兜底层还有一批尚未消化的发现，在这批消化完之前无法如实断言整体已经全部过检查"
- [x] 浮层/模态类组件（Popover/Dropdown/Modal/SideSheet/Tooltip/Popconfirm）均有 Playwright 用例验证焦点归还——核实 Modal/SideSheet/Popconfirm 已有覆盖；Popover/Dropdown 源码里确实实现了 Esc 关闭时的 `triggerNode.focus()` 焦点归还（Dropdown 内部即 `<Popover>`，天然继承），此前只是缺 e2e 验证，已补齐 `toBeFocused()` 断言。Tooltip 核实完全没有任何焦点操作代码，`role="tooltip"` 的既定语义本就不该抢焦点，"焦点归还"对它不适用，不是遗漏。核实过程中顺带发现 Popover 缺少 Semi 一手来源有的"点击浮层外部区域自动关闭"能力（`trigger=click/contextMenu` 时 Semi `foundation.ts` 无条件注册 `clickOutsideHandler`，非可选项），已补齐并同步影响 Dropdown/Select/DatePicker/Cascader 等全部复用 Popover 的组件，新增 e2e 验证；修复过程中发现 TreeSelect 的 e2e 测试因未限定作用域的 `page.getByRole('treeitem', ...)` 选择器与此前 Tree 组件新增的 `role="treeitem"` 产生歧义命中，属于既有回归，已修复限定 `.lotus-tree-select-panel` 作用域
- [x] 表单类组件（Input/Select/Checkbox/Radio/DatePicker 等）的 label 与控件正确关联（`for`/`aria-labelledby`），可通过屏幕阅读器或等效的可访问性树查询工具验证——核实 `Form.Field` 渲染 `<label for={field}>` 且把同一个 `field` 值透传给具体控件的 `id` prop（`field.tsrx` 第112/116行），Input/InputNumber/TextArea/Select 均已声明并消费 `id` prop 建立真实语义关联；Checkbox/Radio 采用 `<input>` 直接嵌套在 `<label>` 内的原生 wrapper 模式（W3C 隐式关联，效果等价于显式 `for`/`id`，不需要额外属性）。`e2e/input/form.spec.ts` 大量使用 Playwright 的 `getByLabel()` 定位控件并操作成功，这个查询方式本身就是通过 `for`/`aria-labelledby`/wrapper 关联工作的，等价于用可访问性树查询工具验证过
- [x] 色彩对比度检查覆盖 Token 层新增的每一个语义色变量，而非仅默认主题色——核实发现 7 语义色相已被 `contrast.test.ts`/`interaction-contrast.test.ts` 覆盖，但 AI 渐变色（`aiColor`）与 Tag 装饰色（16 色）此前完全没有对比度测试（AI 色的 3.11:1 数值之前只在 theme-tokens.spec.md 里手工记录过一次，从未固化为自动化回归）。新增 `ai-color-contrast.test.ts` 与 `interaction-contrast.test.ts` 补充部分，实测数值与之前手工记录（light 模式 3.11/4.35/6.15）完全吻合，交叉验证了记录准确性；同时发现两处此前未记录的真实情况：AI 渐变色暗色模式 `generalActive` 低至 1.57~1.62、Tag 装饰色暗色模式 `yellow`/`amber` 低至 1.34/1.56——均用 Semi 一手来源独立算了一遍，数值与 lotus 实测高度吻合，确认是 Semi 官方本身的固有权衡（`tag/mixin.scss` 的 solid 类型对全部颜色无条件统一用白字），不是 lotus 引入的缺陷，已补充记录到 theme-tokens.spec.md「已知设计权衡」。数据可视化调色板（`chartDataColor`）不承载叠加文字，是图表色块间彼此可区分的色觉友好性维度，不适用本条对比度检查
- [x] 项目层面：CI 中集成自动化 a11y 扫描工具（如 axe-core 的 Playwright 集成），作为兜底而非替代人工 checklist——核实此前完全未落地（无依赖、无配置）。已安装 `@axe-core/playwright`，新增 `e2e/other/a11y-scan.spec.ts` 对 playground 首页做全量扫描，验证方案本身可行且真实发现问题：首次扫描命中 20 类规则、665 条 critical/serious 级别记录（`aria-allowed-attr`/`color-contrast`/`focusable-content`/`button-name` 等）。这个规模的逐条核实（区分真实缺陷 vs demo 写法问题 vs axe-core 对 `color-mix()`/半透明叠加场景的启发式误报）远超本条验收标准"接入基础设施"的范围，经用户确认本次只完成接入、用 `test.skip` 标注已知问题清单存在，不展开排查修复，留待后续专门安排一轮
